<design_decisions>
- DATA PATH (D): a callback, not the FunctionToolsExecuted handler. That handler only sees the model-visible JSON, which deliberately has no nutrients/portion/source and may be shrunk by fit(); adding them would grow the 900-character model budget. So each tool stores a Display on its per-call token (`call.display`) built from the renal result fields (`v.food`, normalized `v.verdict`, `v.nutrients`, `v.portion`, `v.source`) - never from `spoken`. guardTool emits it through a new `display` option AFTER fit(), only when: the result was not the timeout result, `call.timedOut` is false, the fitted result has `ok === true`, and the fitted result still carries its verdict data (`typeof fitted.verdict === 'string'` or `Array.isArray(fitted.results)`; i.e. not the `{ ok:true, say: TOO_LONG }` summary). The emit is wrapped in try/catch, not awaited, and never changes the returned result. This makes "a failed tool never shows a card" structural.
- Verdict words on screen: ok YES, limit SMALL PORTION, avoid NO, unknown CAN'T TELL (the spoken words, upper-cased; "I can't tell" shortened to CAN'T TELL as the user's spec says).
- Size reading of "verdict word >= 110 px tall": font-size (em box) >= 110 px, preferred 150 px. A 110 px cap height (~153 px font) cannot fit SMALL PORTION on one 1160 px line. Flag this in the summary.
- Shelf looks: the card shows the per-food rows (most serious first) like any multi-food look; the voice names the best pick. No extra "best" line on screen.
- Emoji and pictographs are stripped from on-screen text (librsvg draws them as boxes or inconsistently); a name that becomes empty shows "This food".
- Nothing personal: cardSvg/brandSvg take only the Display fields above; extra keys are ignored. No patient name, phone or patient id ever reaches the SVG.
</design_decisions>
