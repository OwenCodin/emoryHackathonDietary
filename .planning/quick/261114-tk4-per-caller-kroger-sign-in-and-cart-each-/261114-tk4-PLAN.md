<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller identity -> filesystem path | patientId (derived from a phone number or random) becomes a folder name |
| caller A call -> caller B call | one agent process serves successive callers; module state outlives a call |
| relay -> local token store | a late sign-in completion writes a refresh token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-tk4-01 | Tampering | tokenDirFor | mitigate | anchored `^[pg][0-9a-f]{24}$` allow-list; anything else returns null and no path is built; tests cover '../x' and mixed traversal |
| T-tk4-02 | Information disclosure | getKrogerStatus / cart token read | mitigate | one sign-in controller per patient; cart builds its token store from tokenDirFor(base, patientId); tests prove B never reads A's tokens |
| T-tk4-03 | Information disclosure | getCartStatus across calls | mitigate | cart `owner` recorded at startCart; any other patient gets a fresh idle status (no items, no cartUrl) |
| T-tk4-04 | Elevation of privilege | demo account reuse by open-access callers | mitigate | only undefined/null/'demo' map to the base folder; caller.mjs gives 'demo' only to PATIENT_PHONE or flag-off |
| T-tk4-05 | Information disclosure | per-caller folders on disk | mitigate | existing secureFolder rules (700, owned by uid, not a symlink, outside the repo) plus 0700 on `callers`; files 0600 |
| T-tk4-06 | Denial of service | controller Map growth from guests | mitigate | cap 64, evict oldest non-demo after cancel() (pending record kept on disk) |
| T-tk4-07 | Information disclosure | guest folders left on disk | accept | holds only a refresh token for an account the guest chose to connect; documented as a known leftover |
</threat_model>
