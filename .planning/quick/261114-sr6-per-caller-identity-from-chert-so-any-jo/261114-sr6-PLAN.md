Verified against the live Chert API (read-only), do not re-probe:
- GET https://app.trychert.com/api/v1/calls?limit=N, headers `Authorization: Bearer $CHERT_API_KEY`, `X-Chert-Project-Id: $CHERT_PROJECT_ID`. Envelope `{ data: { items: [...] }, request_id }`. Each call has `id`, `direction`, `status`, `from: { type: "phone_number" | "email", value }`, `masked_identity`, timestamps.
- Assume GET /calls/<id> returns `{ data: {...call} }`; read it tolerantly (`data.items[0]`, `data`, or the body itself, whichever has a matching `id`), and on a non-2xx or no match fall back to GET /calls?limit=20 and find the id.
- Inbound: the caller joins LiveKit as `chert-bridge-<call id>`; room metadata becomes `{"chert_call":"<id>","chert_bridge_ready":true,...}` at bridge_ready; job metadata may carry `chert_call` (do not rely on it). `agent/agent.mjs` already has `caller.identity` on the inbound path (`linkedIdentity`).
- GET /shared-messages returns `{ data: { items } }` with `id`, `line_id`, `direction` (`inbound`/`outbound`), `state`, `masked_recipient` (`•••dddd`, last four digits of the other party), `created_at`, `text`. No full number on messages.
- Chert refuses a send with HTTP 403, body `error.code` = `shared_reply_window_closed`, until the phone has joined the project AND texted the line a message with words in the last 24 h. Chert's own gate is the real enforcement; our check only decides what the agent says.
- The greeting must be spoken within 10 s of bridge_ready, so the call-start lookup is capped at 1500 ms and must never throw.
- `npm test` runs `node --env-file-if-exists=.env.local --test`, so `.env.local` values ARE in process.env during tests. Every new test must set or inject its own env (follow `withConfig` in actions/text.test.mjs, or pass an `env` object) and must make no network call.
